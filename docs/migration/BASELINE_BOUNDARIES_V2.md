# V2-009 — Fronteras de datos y algoritmos V1

**Estado:** casos límite ejecutados el 25 de septiembre de 2026 mediante [test_v1_boundaries.py](../../tests/test_characterization/test_v1_boundaries.py), más las pruebas científicas existentes. Los datos canónicos V2-004 a V2-006 permanecen congelados. Estas pruebas describen comportamiento, sin corregir formulaciones ni tratar coincidencia numérica como validación física.

| Dominio / caso | Observación V1 | Clasificación y decisión |
|---|---|---|
| Energía: origen ausente; origen con respuesta no nula | Se inserta `(0,0)` o se sustituye la respuesta del origen. | Comportamiento legado del limpiador para **envolventes de magnitudes positivas**; no usarlo para historia temporal. |
| Energía: signo negativo, puntos repetidos, NaN/Inf | Toma magnitudes absolutas, ordena, conserva el mayor esfuerzo en deformaciones repetidas a `1e-12` y descarta puntos no finitos. Si todos son inválidos, rechaza con `ValueError`. | Legado; la eliminación silenciosa de datos individuales requiere contrato explícito antes de reutilizar el motor. |
| Energía: área nula; dominio último sin candidato | Rechaza con `ValueError` de área o de ausencia de candidato. | Rechazo esperado. |
| Energía: ablandamiento y meseta | Devuelve área positiva, máximo y estado `converged` o `best_effort` según tolerancia. | Comportamiento legado. `best_effort` **no** significa aceptación de desempeño. |
| Energía: tolerancia cero con error residual | Devuelve `best_effort` y error relativo positivo, sin excepción. | Legado; la política de avance V2 está pendiente. |
| Mander canónico | Compresión positiva en la API `response`; tracción negativa por `tension_response`; más allá de `epsilon_cu` marca `failed`. | Convención nativa y límite esperado; no normalizar signos dentro del kernel. |
| RDM canónico | Compresión como magnitud positiva en `response`; referencia de tracción positiva en `tension_response`; fuera de `epsilon_su` marca `in_domain=False`. Se construye con `RDM2019SectionModelSet` y caso `bending`, no pasando `restraint_cases` directamente al modelo de una sola condición. | Convención nativa y rechazo de constructor inapropiado; preservar bending/pure compression separados. |
| Mon_MRO canónico | Tracción positiva; compresión `unsupported` y extrapolación a tracción fuera de `eps_u` lanzan `MaterialDomainError`. | Rechazo esperado. |
| Cyc_MP canónico | Historial repetido conserva orden y repeticiones; dos instancias dan la misma respuesta, pero trial/revert/reset de una no altera el estado comprometido de la otra. | Comportamiento legado correcto para aislamiento de estado; sigue etiquetado como verificación algorítmica sintética. |
| XLSX OOXML independiente del writer local | Lee shared string, inline string, blanco, columna `AA`, hoja listada y valor **cacheado** de fórmula. Hoja ausente lanza `ConfigError`. | Comportamiento esperado; el lector no recalcula fórmulas. El XLSX de prueba se construye desde XML ZIP independiente. |
| IDs Stage 02 | Rechaza separadores, `..`, espacios e identificadores vacíos; rechaza identidad de modelo duplicada sin distinguir mayúsculas/minúsculas. | Rechazo esperado. En Windows un archivo con mismo nombre salvo mayúsculas no puede coexistir; la identidad se ejercitó directamente con dos registros de input. |
| Nombres de hoja Stage 03 | `A/B` y `A:B` se sanean ambos a `A_B`; `CON` se acepta como nombre de carpeta pese a ser nombre de dispositivo Windows. | **Defectos/limitaciones V1:** colisión potencial y reserva de nombre no detectadas; crear ID estable separado de etiqueta en V2. |
| `stage_id="../escaped"` de Stage 03 | Se rechaza por control de nombre al resetear, **después** de que `prepare_stage_from_config` cree `<output_root>/../escaped/data` en el temporal. | **Defecto V1 de protección de ruta.** No se probó con una ruta externa real; el test solo usa `tmp_path`. Validar antes de cualquier escritura en una Issue posterior. |
| Rutas de Stage 03 | El libro relativo del YAML se busca desde el CWD, no desde la ubicación del YAML; la raíz de salida se prepara antes de comprobar que el libro existe. | Limitación/defecto V1 reproducido en V2-007. |

Las pruebas existentes en `tests/test_material_models/`, `tests/test_sections/` y `tests/test_stages/` cubren además tangentes, modos de pandeo, inversión por bisección, estados trial/commit/revert, áreas M–φ y cortes. Se añadieron aserciones específicas donde el oráculo faltaba, sin xfail ni modificaciones a esos tests previos. Las unidades de estos casos son deformación adimensional y MPa para materiales; curvatura 1/m y momento kN-m para M–φ. El limpiador de energía es adimensional respecto a las unidades de sus ejes y no convierte unidades.

**Pendientes para Issues posteriores:** colisiones de nombres de hoja/rutas, validación temprana de `stage_id`, semántica de puntos no finitos y decisión de QA para `best_effort`. No se alteraron las respuestas V1 para resolverlos.
